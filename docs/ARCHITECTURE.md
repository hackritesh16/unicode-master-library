# Architecture

## Repository inspection (Phase 1)

The repository contained only a 24-byte `README.md`. It was treated as empty, so the default stack applies: Flutter + Dart, Material 3, SQLite (`sqflite`), `shared_preferences`, Riverpod for state, `go_router` for navigation.

## Layers (Clean Architecture, feature-first)

```
lib/
  core/        theme, constants, errors, unicode utilities (pure Dart, no Flutter imports)
  database/    SQLite schema, migrations, DAOs, importer
  models/      immutable domain entities (UnicodeChar, UnicodeSequence, Design, ...)
  services/    clipboard, share, export, normalization, font transformation
  providers/   Riverpod providers wiring services/repositories to UI
  features/    home, explorer, name_studio, composer, combining_lab,
               emoji_library, favorites, settings
  shared/      reusable widgets (character tile, copy button, search bar)
  main.dart
```

Rules: UI depends on providers; providers depend on services/repositories; the database layer never imports UI. Pure logic (code point parsing, font mapping, combining marks, composition engine) lives in `core/` or feature `domain/` so it can be unit-tested without a device.

## Unicode data pipeline (Phase 3)

1. `tools/build_unicode_db.dart` detects the latest UCD version, downloads the listed files, and verifies them.
2. Parsers produce rows for `characters`, `blocks`, `scripts`, `sequences`, plus an FTS index for name search.
3. Output is a versioned SQLite file generated by the script, not committed. The app imports it in a background isolate on first run and works fully offline afterwards. Optional updates are checked by version number.

## Key design decisions

- Characters and sequences are separate tables; a code point is never assumed to be a visible glyph (category and assignment status are stored).
- Grapheme handling uses Dart `characters`; normalization uses `unorm_dart`.
- The composition engine takes a theme definition plus rules (symmetry, balance, mark limits) and a seeded RNG; uniqueness is enforced per result set.
- Rendering compatibility is advisory only; the app warns rather than promises.
