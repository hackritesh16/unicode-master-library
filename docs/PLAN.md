## Phase 2 notes

Delivered: dark theme and design tokens (`lib/core/theme`), go_router with a six-tab shell, and six section screens. Sections other than Settings are honest placeholders (`PhasePlaceholder`) that name the phase delivering each feature; they contain no fake data.

## Phase 3 notes

Delivered:

- `lib/core/unicode/code_point.dart`: code point parsing, formatting, UTF-8 helpers (surrogates rejected, never silently replaced).
- `lib/core/unicode/ucd_parsers.dart` and `ucd_bundle.dart`: pure-Dart parsers for UnicodeData, Blocks, Scripts, DerivedAge, PropList, DerivedCoreProperties, EastAsianWidth, NameAliases, emoji-data and emoji-test, plus UCD version detection from `ReadMe.txt`.
- `lib/database/unicode_schema.dart` and `unicode_importer.dart`: SQLite schema and a transactional importer (all-or-nothing, so a failed update keeps the old data). `<..., First>/<..., Last>` ranges are stored in `char_ranges`, not expanded.
- `lib/services/ucd_downloader.dart`: downloads the latest release; the version is read from unicode.org, not hardcoded. The file layout was checked against unicode.org (UCD 18.0.0 at the time of writing).
- `lib/providers/unicode_db_provider.dart` and the Settings screen: first-run download, progress, "Check for updates", and Unicode attribution.
- `tools/fetch_ucd.dart`: `dart tools/fetch_ucd.dart` saves the raw files to `data/unicode/raw/<version>/` (git-ignored).
- Tests: code points, UTF-8, all parsers (English, Hindi, combining marks, emoji sequences), importer, rollback, re-import.

Not in Phase 3:

- No search or query API yet (Phase 4).
- The real UCD files have not been downloaded or imported by this code yet; tests use small hand-written fixtures in the official formats. The first real import must be run on a device or emulator.
- Parsing runs in a background isolate (`compute`), but the SQLite writes run on the main isolate in large batches; this may cause visible jank on slow phones and needs on-device measurement.
- "Offline operation" is covered by design (everything is read from SQLite after install) but not by a dedicated automated test yet.
- The downloader has no unit test (it needs a mock HTTP client).
- No private-use/unassigned classification model yet; it is derived from the `characters`/`char_ranges` tables in Phase 4.

## Known limitations

- Code is written without a local Flutter SDK; verification happens in GitHub Actions (`.github/workflows/ci.yml`).
- Dependency versions in `pubspec.yaml` were chosen from memory and may need bumping.
- The `android/` folder is generated by `flutter create` (see README). After generating it, add `<uses-permission android:name="android.permission.INTERNET"/>` to `android/app/src/main/AndroidManifest.xml`, otherwise release builds cannot download the Unicode data.
- No LICENSE file yet: the license is the repository owner's choice.


## Phase 4 notes

Implemented the first usable Unicode Explorer:

- Read-only SQLite query repository with bounded results and parameterized SQL.
- Search by literal character, `U+XXXX` / `0xXXXX` / bare hexadecimal code point, character name, block, script and name alias.
- Code-point lookup also checks compressed `char_ranges`, so large First/Last ranges remain searchable without expanding the database.
- Responsive character grid and detail sheet showing category, block, script, Unicode age, combining class, UTF-8 bytes, aliases and derived properties.
- Copy action for valid Unicode scalar characters; safe display for non-scalar range entries.
- Empty/loading/error states and a route to Settings when the database has not been installed.
- Repository tests cover name/block/script/code-point/literal search, range lookup, unassigned values and detail metadata.

Verification still required: GitHub Actions must pass after this commit, and the first full UCD download/import plus search performance must be checked on a physical Android device. The Explorer currently returns at most 120 results per query; pagination and advanced filters are follow-up work.
